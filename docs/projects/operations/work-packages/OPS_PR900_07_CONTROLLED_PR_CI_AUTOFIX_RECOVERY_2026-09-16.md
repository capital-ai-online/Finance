## Owner-directed scope

This package is the fresh-current-main recovery of the closed/unmerged PR #976 design. The historical branch `agent/operations-pr-ci-autofix-20260916` is search input only and is not used as an integration base or validation authority.

`OPS-PR900-07` is a bounded execution child of the current `OPS-02-CI-01 — Build/Test Cost & Scope Reduction` package. It does not replace or reorder the canonical OPS Roadmap priority established after PR #978; `OPS-PR900-05` and `OPS-PR900-06` remain the Roadmap's normal next-priority sequence outside this explicit Owner-directed recovery scope.

The bounded objective is to prove one safe automatic PR-CI remediation path:

`build-and-test FAIL -> read-only detect/classify -> deterministic patch -> read-only revalidation -> exact-tree write to the same PR branch`.

The historical unrestricted `self-heal-ci.yml` remains suspended/read-only. This package does not restore M10, does not add auto-merge and does not create a second Required Check.

## Recovery finding from closed PR #976

The terminal hosted evidence for PR #976 showed:

- `build-and-test`: PASS;
- Governance: PASS;
- selective CodeQL: PASS;
- Container Security: PASS;
- zizmor: FAIL.

The reproducible zizmor finding was an ad-hoc package installation in `controlled-pr-ci-autofix.yml`: the workflow installed `@github/copilot` outside the repository lockfile at runtime.

Recovery decision: the productive slice contains **no Copilot CLI, no agentic provider fixer and no ad-hoc `npm install`**. TypeScript, unit-test and production-build failures are recognized but held fail-closed with `agentic-engine-not-materialized-in-deterministic-slice`.

## Deterministic failure class

The only productive automatic repair in this slice is the repository-owned README version projection.

Exact failure signature:

```text
[readme-sync] README projection drift detected. Run: npm run readme:sync
```

The fixer reuses the trusted PR-base implementation `scripts/automation/syncReadmeVersions.ts`; dependencies are installed only with the committed lockfile using `npm ci --ignore-scripts`, and the repair command uses the already installed `tsx` binary via `npx --no-install`.

## Eligibility and fail-closed gates

A failed CI snapshot can advance only when all of these are true:

1. source workflow is `.github/workflows/ci.yml` and event is `pull_request`;
2. source conclusion is `failure` and job `build-and-test` is actually failed;
3. exactly one open PR maps to the source head SHA;
4. PR base is `main`;
5. head repository is exactly `capital-ai-online/Finance`;
6. head branch is agent-managed and not `main`;
7. fewer than two previous `fix(ci-autofix): attempt ...` commits exist;
8. original PR scope contains no protected surface;
9. the sanitized failed log contains the exact deterministic README-drift signature.

Protected original PR scope includes `/AGENTS.md`, `.github/**`, `.ai/**`, Governance/ADR/project-roadmap surfaces, `scripts/pr/**`, Security/Governance scripts, dependencies/lockfiles, Node runtime, Docker/Render, server/runtime, Supabase/migrations, Auth, Security, Billing, Entitlement, IAM, Secret and Credential surfaces.

Unknown, infrastructure, dependency-audit, Docker, deployment, supply-chain, TypeScript, test and build failures are not automatically mutated by this slice.

## Patch contract

The candidate patch must satisfy all of these conditions:

- exactly one modified file: `README.md`;
- no create/delete/rename;
- no untracked files;
- no binary diff;
- at most 300 changed lines;
- `git diff --check` PASS;
- no recognized private-key/token-like material;
- patch is generated by the trusted base projection script;
- patch is revalidated in a read-only job with `npm run readme:check`.

## Privilege separation

```text
failed CI workflow_run
        |
        v
read-only plan
(actions/read + contents/read + pull-requests/read)
        |
        v
deterministic README projection
(contents/read; npm ci --ignore-scripts; no provider token)
        |
        v
short-lived artifact
(patch + final README; SHA-256)
        |
        v
read-only validation
(apply patch -> trusted guard -> readme:check -> Git tree/blob identity)
        |
        v
privileged exact-tree writer
(contents/write + pull-requests/read; NO PR checkout; NO PR/dependency execution)
```

The privileged job does not check out the PR at all. It re-reads the open PR, current `main` and branch ref, verifies unchanged PR/base/head/repository identity, verifies the patch SHA-256, creates only the validated README Git blob, creates a tree from the current PR-head tree, compares that tree to the read-only validated tree, creates a child commit and updates the branch ref with `force: false`.

This design removes the `workflow_run` privileged-checkout boundary that GitHub explicitly warns about for untrusted PR content.

## Required-check boundary

The controller never creates a check run or commit status named `build-and-test`. After an autofix write, the new PR head remains subject to authoritative hosted CI and Human/CODEOWNER merge authority.

GitHub `GITHUB_TOKEN` recursion protections mean a workflow-originated repository write cannot be treated as proof of an unattended CI retrigger. This package therefore does not claim autonomous end-to-end retriggering.

## Separate GitHub App Controller boundary

A future unattended retrigger may use a narrowly scoped GitHub App installation identity, but that is **not activated by this package**.

Current repository contracts require separate explicit Human/Owner authorization before GitHub App creation/installation, repository selection, permission grants, OAuth/MCP connection changes, Vault/secret changes or equivalent provider mutation. The normal target remains a short-lived installation token and the controller must remain separate from the broader 04A Reader identity/capability surface.

Until that protected mutation is separately authorized and proven, controller state is:

`HELD_EXTERNAL_OWNER_AUTHORIZATION`.

No PAT or retired M10 mechanism is introduced as a workaround.

## Validation contract

Repository implementation exit requires exact-head hosted evidence for the implementation PR:

1. `build-and-test` PASS for the applicable C-N scope;
2. Governance/workflow-security PASS;
3. zizmor PASS — specifically no ad-hoc package-install finding;
4. applicable selective provider/security checks PASS or truthfully classified by current policy;
5. no merge by an agent.

Post-merge behavioral evidence then requires one real suitable failed PR snapshot to produce either:

- deterministic README patch -> read-only revalidation -> exact-tree new PR head; or
- an evidence-backed `HELD` / fail-closed decision.

A new PR-head CI result is not fabricated. `NOT RUN`, approval-required or controller-held states remain distinct from PASS.

## Rollback

Rollback uses a fresh OPS branch from then-current `main` and suspends `controlled-pr-ci-autofix.yml` to manual/diagnostic-only or removes its automatic trigger through the normal workflow-security-reviewed PR path. It must not restore the historical unrestricted Self-Heal implementation.

## Exit gate

`OPS-PR900-07` repository implementation exit is reached when the deterministic slice passes exact-head hosted workflow/security checks and the old zizmor ad-hoc-install finding is absent. Behavioral exit is reached after the first real eligible failure demonstrates bounded patch/revalidation/write or a reproducible fail-closed result. Provider/controller activation remains a separate protected gate.
