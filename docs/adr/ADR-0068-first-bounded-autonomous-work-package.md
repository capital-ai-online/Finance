# ADR-0068 — First Bounded Autonomous Work Package

Status: PROPOSED / OWNER-DIRECTED SA4 BOOTSTRAP
Date: 2026-08-12
Authority: ESS-0021, ADR-0065, ADR-0059, ADR-0067

## Context

SA3B has proven the execution-host boundary with a real GitHub Actions OIDC workload identity, a durable M5 authorization event before the repository side effect, and a correlated terminal outcome event. A separate stale-base probe has proven zero side effects for an invalid execution request.

SA4 must now prove the first bounded autonomous repository work package without widening the agent into a general-purpose GitHub operator.

The first pilot intentionally has no production effect. It creates exactly one deterministic documentation evidence file and opens one draft pull request. Human review and Human-only merge remain mandatory.

## Decision

The existing GitHub Actions execution-host pattern is extended with a dedicated SA4 workflow and exact Owner-approved REM.

Canonical chain:

`OWNER SA4 ISSUE → TRUSTED main WORKFLOW → STRICT REQUEST VALIDATION → SA3B CLEANUP GATE → GITHUB OIDC → M5 BRANCH AUTH → BRANCH → M5 BRANCH OUTCOME → M5 COMMIT AUTH → EXACT DETERMINISTIC FILE COMMIT → TARGETED VALIDATION → M5 COMMIT OUTCOME → M5 PR AUTH → DRAFT PR → M5 PR OUTCOME → HUMAN REVIEW → HUMAN MERGE`

The pilot does not delegate `CI_REQUEST`, deployment, production mutation or merge.

## Exact pilot output

The only repository content path the pilot may create is:

`docs/evidence/sa4/SA4_FIRST_AUTONOMOUS_WORK_PACKAGE.md`

The Issue body cannot provide file contents, shell commands, arbitrary paths, PR titles or workflow definitions. File content and PR metadata are generated by trusted code from bounded execution metadata only.

## SA3B cleanup prerequisite

SA4 is not executable while the successful SA3B probe branch exists:

`agent/sa3b-host-probe-20260812b`

The SA4 workflow checks this GitHub ref before OIDC acquisition and before any broker authorization. Presence of the branch causes fail-closed termination with zero SA4 repository side effects.

This allows the SA4 implementation to be reviewed and merged without falsely declaring the SA3B lifecycle complete.

## REM

The sole first-pilot mandate is:

`.ai/mandates/REM-SA4-PILOT-001.json`

It is bound to:

- Repository: `SvenKulessa/Finance`;
- Base: `main`;

All reserved mutation classes from ADR-0065 remain denied.

## Per-side-effect audit rule

Each of `BRANCH`, `COMMIT` and `PR` requires its own authorization event and its own terminal outcome event.

An authorization response is usable only when all of the following are true:

- verdict `ALLOW`;
- valid `supabase:agent_audit_events:<id>` reference;
- `auditBoundExecutionPermitted=true`;
- capability equals the exact requested operation;
- mandate, path, branch and current-head binding match the trusted workflow state.

No earlier permit may be reused for a later capability.

## Deterministic commit

The workflow itself creates the evidence document from trusted values:

- mandate ID;
- roadmap item;
- issue number;
- workflow run ID;
- base SHA;
- branch name;
- preceding audit references.

The issue cannot inject Markdown content. Before the COMMIT outcome is recorded, the workflow re-reads the committed file and verifies its SHA-256 digest against the locally generated trusted content.

## Draft PR only

PR authority is limited to creating one draft PR from the exact SA4 branch to `main`. The generated PR body identifies the mandate and audit references and explicitly states that CI success is not merge authorization.

The host does not approve, mark ready, merge, deploy or alter repository protection.

## Failure and rollback

Before a side effect: any validation/OIDC/policy/audit failure means no side effect.

After branch creation but before a successful commit: the workflow may delete the exact pilot branch as bounded rollback.

After commit creation but before PR creation: the exact pilot branch may be deleted as bounded rollback because no PR exists.

If a draft PR was created but its terminal audit outcome cannot be persisted, the workflow closes that exact draft PR and deletes the exact pilot branch as bounded rollback, then fails.

Rollback authority cannot target `main`, another branch or another PR.

## Trust-root boundary

SA4 must not be capable of modifying its own workflow, OIDC verifier, broker, REM, parser, IAM/REM evaluator or audit adapter. The bootstrap therefore extends the Systemadmin self-authority protection before the pilot is activated.

## CI budget

Opening the draft PR may trigger lightweight governance/Owner-gate workflows. The Systemadmin host does not request the expensive final CI itself. The existing Human current-head review/attestation gate remains responsible for the single final `build-and-test` until M10 Passkey-only authorization is actually cut over.

## Human boundary

`MERGE` remains non-delegable. No model, workflow, REM, audit permit, GitHub token or CI result constitutes merge approval.

## Exit criteria

SA4 reaches `VERIFIED PASS` only after:

1. SA3B successful probe branch is deleted;
2. SA4 bootstrap PR is Human-reviewed, CI PASS, Human-merged and bootstrap branch deleted;
3. a fresh Owner SA4 Issue runs from the exact current `main`;
4. separate durable authorization/outcome pairs exist for BRANCH, COMMIT and PR;
5. the committed file is the exact allowlisted deterministic artifact;
6. one draft PR is created and points to the exact audited commit;
7. no production mutation occurred;
8. Human merge boundary remains intact;
9. pilot branch is deleted after the eventual Human merge;
10. evidence, roadmap and traceability are synchronized.

## Consequences

SA4 increases autonomous repository execution from branch-only proof to a bounded branch/commit/draft-PR work package. The increase is deliberately narrow and evidence-driven. External production mutations remain blocked for SA5+ and require their own architecture and Owner assurance.
