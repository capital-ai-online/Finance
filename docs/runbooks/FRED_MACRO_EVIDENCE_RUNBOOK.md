# FRED Macro/Rate Evidence — Production Runbook

**Scope:** CAPITAL-AI server-side macro/rate evidence  
**Related:** ADR-0022, ADR-0023, `src/services/macroRateEvidence.ts`, `src/services/macroRiskRegime.ts`

## 1. Runtime configuration

The production runtime expects the server-side environment variable:

```text
FRED_API_KEY
```

The value must never be committed to the repository, exposed through a `VITE_` variable, returned by an API response, logged, or copied into provenance/evidence records.

The application repository only defines the environment-variable contract. Secret creation and rotation remain an external production operation.

## 2. Approved FRED series

Only reviewed series in `APPROVED_FRED_SERIES` may be requested through CAPITAL-AI:

- `DGS2` — U.S. Treasury 2-Year Constant Maturity
- `DGS10` — U.S. Treasury 10-Year Constant Maturity
- `FEDFUNDS` — Federal Funds Effective Rate
- `CPIAUCSL` — Consumer Price Index for All Urban Consumers

Arbitrary client-supplied FRED series IDs are not permitted.

## 3. Verification endpoints

After deployment, validate the server-side evidence boundary with:

```text
GET /api/registry/macro/fred/DGS10
GET /api/registry/macro/fred/DGS2
GET /api/registry/macro/risk-regime
```

Expected successful FRED evidence response characteristics:

- HTTP 200
- `status: READY`
- `provider: FRED`
- `executionPriceEligible: false`
- non-empty `evidenceIds`
- secret-free `sourcePath`
- `x-correlation-id` response header

The risk-regime endpoint is successful only when DGS2 and DGS10 contain a common observation date. It must never manufacture a curve regime from mismatched dates.

## 4. Fail-closed behavior

The following conditions must not produce default macro data:

- missing/invalid `FRED_API_KEY`
- FRED HTTP failure
- timeout
- malformed observations
- no numeric observations
- DGS2/DGS10 without a common observation day

Expected states include `SOURCE_UNAVAILABLE` or `EVIDENCE_INCOMPLETE`. No asset score or execution price is generated by the macro evidence layer.

## 5. Runtime observability

Every FRED call records:

- Provider Health through `recordProviderHealth()`
- routing success/failure and latency through `recordMarketDataProviderOutcome()`
- correlation ID at the API boundary
- stable Evidence IDs for accepted observations

These observations feed the existing Supervisor and `RUNTIME-01` compliance evidence path. A provider that was never called must not be represented as healthy by assumption.

## 6. Security verification

Before release, confirm:

1. repository search contains no real FRED key value;
2. `.env.example` contains only `FRED_API_KEY=`;
3. browser bundles do not contain `FRED_API_KEY` or a `VITE_FRED_*` variable;
4. API responses do not contain `api_key=`;
5. logs do not print the full outbound FRED URL containing the secret;
6. CI vulnerability, TypeScript, Vitest, build and deployment-readiness gates are green.

## 7. Bond / cross-asset boundary

FRED evidence may provide rate-curve or macro context, but it does not by itself authorize Bond Scoring. ADR-0022 remains the activation gate for Fixed-Income scoring.

The versioned Macro Risk Regime contract is evidence/context only and must not be presented as an investment recommendation or tradable market price.

## 8. UI / graphics

This runbook and the associated implementation do not require or authorize graphical changes.
