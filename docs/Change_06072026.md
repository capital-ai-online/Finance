# CAPITAL-AI Platform Change Log
**Date: 06.07.2026**
**Release Version: 0.5.5 (Beta-Phase)**

---

## 🛠️ Summary of Changes

This document captures the platform structural modifications, new endpoints, telemetry logic, and centralized middleware architectures implemented on July 6, 2026. All additions strictly respect sensitive data privacy mandates, enforce rigorous validation, and prevent data leakage.

---

### 1. Centralized Error Handling Architecture
Introduced a standardized, type-safe error pipeline to guarantee uniform API response formats and prevent diagnostic exposure in production environments.

* **File Added:** `src/utils/errors.ts`
  * Implemented `AppError` base class extending native `Error` with properties: `message`, `statusCode`, `errorCode`, `timestamp`, `details`, and `cause`.
  * Defined specialized, self-documenting subclasses:
    * `ValidationError` (400 - `VALIDATION_ERROR`)
    * `AuthenticationError` (401 - `AUTHENTICATION_REQUIRED`)
    * `AuthorizationError` (403 - `ACCESS_DENIED`)
    * `NotFoundError` (404 - `RESOURCE_NOT_FOUND`)
    * `RateLimitError` (429 - `RATE_LIMIT_EXCEEDED`)
    * `DatabaseError` (500 - `DATABASE_ERROR`)
    * `ConfigurationError` (500 - `CONFIGURATION_ERROR`)
    * `InternalServerError` (500 - `INTERNAL_SERVER_ERROR`)
    * `ExternalApiError` (502 - `EXTERNAL_API_ERROR`)

* **File Added:** `src/middleware/errorHandler.ts`
  * Built global Express-style error-handling middleware (`globalErrorHandler`).
  * Normalizes incoming application errors and generic HTTP/JWT/Validation helper errors.
  * Dynamically extracts the active AsyncLocalStorage context `requestId` to uniquely tag each request trace.
  * Restricts full stack traces to local development environments (`process.env.NODE_ENV !== 'production'`) and ensures clean, sanitized JSON error payloads are delivered to external callers.
  * Interfaced with the Winston logging daemon to pipe unhandled exception signatures securely.

---

### 2. High-Precision Performance & Telemetry Engine
Added a unified instrumentation layer to measure CPU and memory footprint across latency-critical sections, with strict masking of PII or client metadata.

* **File Added:** `src/utils/telemetry.ts`
  * Implemented `TelemetryEngine` as a thread-safe Singleton instance.
  * Added high-resolution duration calculation via `process.hrtime()`.
  * Tracks CPU consumption (`process.cpuUsage()`) and memory allocation differentials (`process.memoryUsage().heapUsed`).
  * Pipes structured metrics (`memoryDeltaKb`, `cpuTimeMs`, `durationMs`) safely into centralized secure logs without leaking IP addresses or session particulars.

---

### 3. Secure Authorized Diagnostics Endpoint
Created a real-time connectivity validation interface to audit critical dependencies without exposing telemetry metrics or back-end credentials to unauthorized third parties.

* **File Added:** `src/routes/healthRoutes.ts`
  * Implemented secure `x-health-check-token` and `x-orchestrator-admin-token` Bearer header authorization check.
  * Executes a fast connection test query against Supabase PostgreSQL if database credentials are present.
  * Assesses upload directory write permissions locally in the sandbox container.
  * Calculates system health status (`healthy`, `degraded`, or `unhealthy`).
  * Returns detailed process info, platform architecture, uptime state, and environment presence (Stripe, Gemini, Supabase config flags) under Version **0.5.5**.

* **File Modified:** `server.ts`
  * Registered the health router dynamically under `/api/health-check`.
  * Connected to Express router pipeline prior to the standard static fallback.
